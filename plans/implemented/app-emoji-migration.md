# Migrate every custom emoji to application emojis (lossless WebP)

Follow-up to tracker #0117, agreed with the project owner 2026-09-23.

## Why

Today's 35 custom emojis are **guild emojis**: uploaded by hand to one server, their ids pasted
into `qapbot/emojis.py`'s `BotEmojis`. #0117 introduced the first **application emoji**
(`cwl_bench`), which the bot uploads itself. Moving everything to application emojis means:

- no server's 50-slot emoji budget is consumed, and no server admin can delete them;
- a new icon is "commit the art + one manifest line", not "upload, copy the id, edit code";
- 2000 slots per application instead of 50 per server.

## Format

- **Masters stay as they are** in `qapbot/icons/`: SVG for the 13 vector icons (also what the
  Activity bundles), WebP for the 24 TH/hero rasters.
- **Upload artifacts** are generated into `qapbot/icons/emoji/<name>.webp`: **lossless** WebP
  (lossy smears thin icon edges), square, transparent background.
  - SVG → rasterised at 128×128.
  - Raster → padded to a square canvas with **no resampling**, so they look exactly as today
    (several are 74×100, 63×100, …; upscaling would blur them).
- Generated by `activity/client/scripts/build-emoji-assets.mjs` with `sharp` (declared as a
  devDependency — it is only present transitively today). Artifacts are committed; the bot never
  converts anything at runtime.

## Single manifest

`qapbot/icons/emoji_manifest.json` — `[{"attr", "name", "source"}]`, read by both the generator
and the bot, so the emoji set can never disagree between the two.

## Runtime

- `BotEmojis` keeps its hardcoded guild-emoji ids **as fallbacks**. A metaclass resolves every
  upper-case attribute at lookup time: the application emoji if resolved, else the constant.
  Covers `BotEmojis.X` and `getattr(BotEmojis, "THxx", default)` — all 44 call sites, unchanged.
  Audited: no import-time or default-argument captures of these values exist.
- `ensure_application_emojis(bot)` at INIT-STEP-6b: one `fetch_application_emojis()` resolves
  everything already uploaded (fast, synchronous). Anything missing is uploaded in a tracked
  **background** task, paced, so a first boot with ~37 uploads never blocks startup; until each
  lands, the guild-emoji fallback is used, which still renders.
- `cwl_bench` joins the manifest; its fallback stays 🪑 (it has no guild emoji).
- Guild emojis are **not deleted**: already-posted messages keep rendering.

## Tests

Manifest ↔ `BotEmojis` coverage both ways; every artifact exists, is square, lossless WebP,
≤ 256 KiB; resolution/fallback via attribute and `getattr`; reuse vs upload vs failure;
background upload doesn't block.
